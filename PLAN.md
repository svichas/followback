# Followback — plan

Chrome extension (Manifest V3). Open it on your Instagram profile, scan your followers and following, see who doesn't follow you back, and unfollow them at a pace Instagram tolerates.

## How it works

- **No API key.** A content script runs inside your logged-in `www.instagram.com` tab and calls the same internal endpoints Instagram's own Followers dialog calls. Your session cookie authenticates them; `X-IG-App-ID` is a fixed public value instagram.com sends for everyone. (Meta's official Graph API can't list followers or unfollow.)
- **Side panel, not a popup**, so the UI stays open during a scan or a long unfollow run.
- **`chrome.storage.local` is the single source of truth.** The content script writes progress and results; the panel only renders from storage and listens to `chrome.storage.onChanged`. Closing or reopening the panel loses nothing.

```
side panel ──sendMessage(ping | scan | unfollow)──▶ content.js (instagram.com tab) ──fetch──▶ /api/v1/…
     ▲                                                   │
     └──────────── chrome.storage.local ◀────────────────┘  status, profile, lists, unfollowed
side panel ──storage.set({ stopAt })──▶ content.js stops (works even after the panel was reopened)
```

## Contracts (both Sonnet agents code against these — do not change them)

### Shapes

```js
User    = { id: string, username: string, fullName: string, pic: string, verified: boolean, isPrivate: boolean }
Profile = { id: string, username: string | null, fullName: string, pic: string, followerCount: number | null, followingCount: number | null }
// id comes from the ds_user_id cookie; the rest is read off your own profile page when the tab is on it (else null / '')
Status  = {
  state: 'idle' | 'scanning' | 'unfollowing' | 'done' | 'stopped' | 'error',
  job: 'scan' | 'unfollow' | null,
  phase: 'followers' | 'following' | null,  // while scanning
  done: number, total: number | null,       // progress of the current phase / unfollow queue
  message: string,                          // one human-readable line
  resumeAt: number | null,                  // epoch ms while pausing; the panel renders a countdown
  at: number                                // epoch ms of this write
}
```

### `chrome.storage.local` keys

| Key | Type | Written by | When |
|---|---|---|---|
| `status` | `Status` | content.js (panel only on Stop) | often |
| `profile` | `Profile` | content.js | end of a **complete** scan |
| `followers` | `User[]` | content.js | end of a complete scan |
| `following` | `User[]` | content.js | end of a complete scan |
| `unfollowed` | `string[]` (user ids) | content.js | after each successful unfollow; reset to `[]` by a new scan |
| `scannedAt` | `number` | content.js | end of a complete scan |
| `stopAt` | `number` | panel | Stop clicked |

`profile`, `followers`, `following`, `unfollowed: []`, `scannedAt` are written in **one** `set()` call at the end of a scan. A stopped or failed scan writes none of them, so the previous results stay intact.

### Messages (panel → content script)

`chrome.tabs.sendMessage(activeTabId, msg)`. Every reply is `{ ok: true, … }` or `{ ok: false, error: string }`. Replies are synchronous; long work continues in the background and reports through `status`.

| `msg` | Reply |
|---|---|
| `{ type: 'ping' }` | `{ ok: true, username: string \| null, busy: boolean }`: `username` is the first path segment when the page has a link to `/<segment>/followers/` (a profile page), else `null`. Display hint only, never a gate. |
| `{ type: 'scan' }` | `{ ok: true }` when started; `{ ok: false, error }` if a job is already running |
| `{ type: 'unfollow', ids: string[] }` | same |

**Stop:** the panel calls `chrome.storage.local.set({ stopAt: Date.now(), status: { ...status, state: 'stopped', message: 'Stopped.', resumeAt: null } })`. The content script listens for `stopAt` changes and ends its loop within about 1 second. The panel's own status write means the UI recovers even if the Instagram tab is gone.

If `sendMessage` rejects (not an Instagram tab, or the tab was open before the extension was installed), the panel shows the "open / reload Instagram" state.

**Liveness:** a job dies silently with its tab, so a `scanning`/`unfollowing` status counts as running only while `Date.now() - max(at, resumeAt ?? 0) < 2 min`. A live job writes at least that often, and long rests set `resumeAt`. The panel shows a status that has gone quiet as "Interrupted — the Instagram tab was reloaded or closed." and lets you start again. content.js refuses a new job while any tab's job is alive.

## Engine — `content.js`

Requests mirror a known-working 2026 web client ([adrigo/unfollowers-for-instagram](https://github.com/adrigo/unfollowers-for-instagram), `src/api.ts`). An earlier version called `users/web_profile_info`, which Instagram throttles hard, and every scan got HTTP 429.

All requests go to `https://www.instagram.com/…` with `credentials: 'include'` and these headers: `X-IG-App-ID: 936619743392459`, `X-ASBD-ID: 198387`, `X-Requested-With: XMLHttpRequest`. The unfollow POST also sends `Content-Type: application/x-www-form-urlencoded`, `X-CSRFToken: <csrftoken cookie>` and `X-Instagram-AJAX: 1`.

| Call | Endpoint | Response used |
|---|---|---|
| Followers | `GET api/v1/friendships/<id>/followers/?count=25[&max_id=<cursor>]` (Instagram serves about 25 per page anyway) | `users[]`, `next_max_id` (absent on the last page) |
| Following | `GET api/v1/friendships/<id>/following/?order=date_followed_latest[&max_id=<cursor>]` | same |
| Unfollow | `POST web/friendships/<targetId>/unfollow/`, no body | `status: 'ok'` |

`<id>` is the `ds_user_id` cookie, so a scan always reads the logged-in account, whatever page the tab is on. The panel's label and totals (`username`, `pic`, `followerCount`, `followingCount`) are read off the page only when it is your own profile, meaning it links to `/accounts/edit/`. They are best effort, cost no request, and fall back to `null` or `''`.

Instagram user → `User`: `id = String(u.pk_id ?? u.pk)`, `fullName = u.full_name || ''`, `pic = u.profile_pic_url || ''`, `verified = !!u.is_verified`, `isPrivate = !!u.is_private`.

Failures:
- **Rate-limited:** HTTP 429, or JSON with `spam: true` or `message: 'feedback_required'`.
- **Redirected:** the fetch was redirected to a login or security-check page. Message: "finish it on instagram.com, then try again."
- **Other errors:** any other non-OK HTTP response, or JSON `status !== 'ok'`. Message: `feedback_title || message`.
- **Logged out:** `login_required`, or no `ds_user_id` cookie, maps to "Log in to Instagram in this tab first."

**Scan**
1. Page through followers, then following. Dedupe by id with a `Map`. After each page, write status `{ state: 'scanning', phase, done: map.size, total: <count from the page, or null> }`. Wait a random 1–2.5 s between pages.
2. A rate limit on the **very first request** fails at once: "Instagram is rate-limiting your account (HTTP 429). Wait 15–30 minutes, then scan again — retrying sooner tends to extend it." The account is already limited, and retrying only prolongs it. A rate limit later in the scan waits 2 minutes (status message plus `resumeAt`) and retries, giving up with the same message after 3 retries in a row.
3. Stopped → save nothing and finish with "Scan stopped — nothing saved." Complete → one `set()` call (see contract), then `done` with "Found N followers and M following."

**Unfollow `ids`**
1. Queue = members of `following` whose id is in `ids`, **not** in `followers` and **not** in `unfollowed`. Cap the queue at 150 per run. Re-checking against `followers` here means a panel bug can never unfollow someone who follows you.
2. For each user, write status (`Unfollowing @x…`, `done`/`total`), POST unfollow, then immediately append the id to `unfollowed` in storage.
3. Pacing: wait a random 10–20 s between unfollows. After every 5th unfollow, pause 5 minutes with `resumeAt` set and the message "Pausing to stay under Instagram's limits". That works out to about 45 per hour.
4. Rate-limited → stop with `error`: "Instagram is limiting unfollows right now — wait a few hours (ideally a day) before continuing." Never retry an unfollow.
5. Done → "Unfollowed N accounts." When the cap was hit, append " Stopped at 150 for today — run again tomorrow to avoid an Instagram block."

**Plumbing**
- Pacing constants sit at the top of the file with one-line comments.
- Waits tick in 1-second steps that check the stop flag, so Stop takes effect within about 1 s and tests can stub `setTimeout`.
- An in-memory status object is merged and written as a whole. This avoids read-modify-write races.
- One job across all tabs (see Liveness). Loading a page never rewrites another tab's status.
- `onMessage` only answers `ping`, `scan` and `unfollow`, and only one job runs at a time.

**Test (`test/content.test.js`)** loads `content.js` in `node:vm` with stubbed `chrome`, `fetch`, `document`, `location`, `sessionStorage` and an instant `setTimeout`. It drives the script only through the `onMessage` handler and storage, so `content.js` has no exports and no test hooks. Cases:
- The scan paginates, dedupes and saves everything in one `set()` call.
- A scan always reads the `ds_user_id` account. It takes the label and totals only from your own profile page.
- A rate limit on the first request fails fast; one mid-scan is retried.
- Unfollow never touches a follower, an already-unfollowed id, or an id missing from `following`, and it persists `unfollowed`.
- Unfollow stops on the first rate-limit and makes no further unfollow calls.
- `stopAt` halts a running job.

## UI — side panel

The panel is about 360 px wide by default and must work from 320 to 600 px. It uses the system font stack, light and dark themes via `prefers-color-scheme`, and the Instagram gradient as its only accent (`linear-gradient(45deg, #feda75, #fa7e1e, #d62976, #962fbf, #4f5bd5)`). The danger color is `#ed4956`.

1. **Header**: a gradient brand mark plus "Followback". A profile chip on the right shows the avatar and `@username` from `profile`, or the username from the ping.
2. **Context card**, which changes with state:
   - **Not reachable**: "Open Instagram" button (`chrome.tabs.update(tabId, { url: 'https://www.instagram.com/' })`), plus "Already open? Reload the tab" (`chrome.tabs.reload`).
   - **Ready**: big gradient button "Scan followers & following". Its hint reads "@user" when known, else "Open your profile first".
   - **Scanning**: a progress row for each phase (Followers 340 / 1,234, then Following) and a Stop button.
   - **Error**: a banner with the message and a "Try again" button.
3. **Stats** (once a scan exists): three tiles: Followers, Following and Not following back (accented). Clicking a tile selects its list. Below them, "Scanned 12 min ago" and a Rescan button. When `followers.length < 0.95 * profile.followerCount`, show the warning "Only found X of Y followers — some people may be wrongly listed as not following back."
4. **List**:
   - Segmented tabs: Not following back (default), Followers, Following. Each shows its count.
   - A search box filters by username or full name.
   - Rows: 36 px round avatar (falls back to initials on error, since Instagram CDN URLs expire), bold username linking to `https://www.instagram.com/<u>/` in a new tab, a verified badge, and the full name muted.
   - Only the Not following back tab gets a checkbox per row (checked by default) and a "Select all" header. Ids the user unticks are kept in panel memory. Rows in `unfollowed` appear dimmed with an "Unfollowed" pill and no checkbox.
   - Empty states: "Scan your profile to see who doesn't follow you back.", "Everyone you follow follows you back 🎉", "No matches".
5. **Sticky footer** (Not following back tab only):
   - The danger button reads "Unfollow N selected".
   - Clicking it opens an inline confirm step, not `confirm()`. Copy: "Unfollow N accounts? About 45 per hour, max 150 per run (≈ X min). Keep the Instagram tab open.", then Cancel / Yes, unfollow.
   - While running: a progress bar showing "Unfollowed 12 / 87", the status message, a live countdown from `resumeAt`, and a Stop button.

**Rules**
- Build rows with `createElement` and `textContent`. Names come from Instagram and are untrusted, so never use `innerHTML` with them.
- Lists can exceed 5,000 rows. Re-render the list only when `followers`, `following`, `unfollowed` or `profile` change, or when the tab or search changes, never on `status` writes. Rows use `content-visibility: auto`.
- Countdowns come from a 1-second interval that updates only the countdown text.
- Re-ping the active tab on load, `chrome.tabs.onActivated`, `chrome.tabs.onUpdated` (active tab) and window focus.
- Accessibility: real `<button>`s, labelled inputs, `role="tablist"`/`tab` with `aria-selected`, an `aria-live="polite"` status region, visible `:focus-visible` rings, AA contrast. Respect `prefers-reduced-motion`.

**Preview harness** (scratchpad, not the repo): a fake `chrome` (`stub.js`) with mock data and a `build.sh` that copies the panel files and icons and injects the stub. Scenarios are picked by URL hash: `#none`, `#ready`, `#scanning`, `#results`, `#unfollowing`, `#error`. This lets the panel be screenshotted in the browser without loading the extension.

## Safety rails

- Unfollows are paced at about 45 per hour, with at most 150 per run. The run stops on the first rate-limit and never retries an unfollow.
- Unfollowing requires an inline confirm step. Per-row checkboxes let you keep some accounts.
- Partial scans are never saved, so an incomplete followers list can't mark real followers as non-followers.
- The content script re-checks that every target isn't a follower.
- Permissions: `storage`, `sidePanel` and `unlimitedStorage` (large accounts can exceed the 10 MB default). No host permissions, because the content script's same-origin `fetch` doesn't need them.

## Build order (agents)

1. In parallel: **Sonnet** builds the engine (`content.js` and test), **Sonnet** builds the UI (side panel and preview harness), **Haiku** builds the shell (`manifest.json`, `background.js`, icons).

   - Screenshot every preview scenario in light and dark.
   - Fix mismatches.

## Try it

1. Go to `chrome://extensions` and turn on **Developer mode**.
2. Click **Load unpacked** and pick this folder.
3. Open `instagram.com/<you>` (reload the tab if it was already open) and click the Followback toolbar icon.

## Not building (say if you want any)

Whitelist that persists across scans, CSV export, history between scans, a "fans" tab (followers you don't follow back), multiple accounts, Firefox.

## Risks

- The endpoints are undocumented. If Instagram changes them, only `content.js`'s request paths need updating.
- Automating unfollows breaks Instagram's terms. The pacing makes an action block less likely but can't rule it out.
- Nothing here can be tested against live Instagram from this machine; the first real run is yours.
